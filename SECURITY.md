# Security policy

## Reporting a vulnerability

Do not report security vulnerabilities in public GitHub issues or pull
requests.

Email security@vaif.studio. Include:

- the `VaifClient` version and the platform and OS version where you found the
  issue;
- a description of the vulnerability and its impact;
- the steps or code needed to reproduce it;
- any request IDs, logs or proof-of-concept code that help, with API keys,
  access tokens and other people's personal data removed.

The same address handles vulnerabilities in the VAIF Studio API and platform.
It is also published in [security.txt](https://vaif.studio/.well-known/security.txt).

## What happens next

We confirm that we received your report, investigate it, and keep you informed
as we work on it. If we need more information, we ask you at the address you
wrote from. When a fix is ready, we release it in a new version, describe it in
[CHANGELOG.md](CHANGELOG.md), and credit you if you want to be credited.

Please give us time to release a fix before you disclose the issue publicly.
VAIF Studio does not take legal action against good-faith research that stays
away from other people's data and gives us time to fix the issue before it is
made public. The full disclosure policy is at
[vaif.studio/security](https://vaif.studio/security/#disclosure).

## Supported versions

| Version | Supported |
|---|---|
| 1.x | Yes |
| 0.1.0, 0.1.1 (retracted) | No |

Security fixes are released as new 1.x versions. Update to the latest 1.x
release to receive them.
